# Lab routes

Quaywork, an invented team workspace (company "Halden Robotics"). Every workspace page needs a login
(`/login`, username `first.last`, password `Password.123`; rollouts use `POST /__rl/login {"user": ...}`).
Times are shown in UTC. The site clock starts at 2026-03-16 15:00 UTC (`WSB_LAB_CLOCK` overrides).

## Hosts

| Host | Serves |
|---|---|
| main (`lab.wa`, `127.10.<i>.8`, or `127.0.0.1:<port>` in dev) | everything below except `/pay/*` |
| payment host (`labpay.wa`, `127.10.<i>.18`, or `localhost:<port>` in dev) | only `/pay/*` (and static files) |

The payment host is a different *site* for the browser, so the invoice page's payment frame is a
cross-site, out-of-process frame. Use `127.0.0.1` (not `localhost`) for the main host in dev.

## Pages

| Route | What |
|---|---|
| `GET /` | home: your open tickets, tiles |
| `GET /chat`, `GET /chat/:channel` | channels; a channel opens at its newest 30 messages, scrolling up loads 30 older ones at a time (prepend, view kept in place). Composer: Enter sends, typing autosaves a draft |
| `POST /chat/:channel` (`body`) | no-JS post |
| `GET /ops`, `GET /ops/queues/:slug` | queues; a queue is a long virtualized list of tickets (rows fetched in chunks) |
| `GET /ops/tickets/:key`, `POST /ops/tickets/:key/comments` (`body`), `POST /ops/tickets/:key/status` (`status`) | ticket detail, comment, status |
| `GET /docs`, `GET /docs/:slug` | planning docs: sheets in a shadow-DOM grid (tabs); "Conversation" toggles a pane with the tracker and its change history (fetched on open, removed on close) |
| `GET /kb`, `GET /kb/:slug` | playbooks: long articles with "Checkpoint CP-nnnn" boxes |
| `GET /crm/accounts` (`?q=`, `?page=`), `GET /crm/accounts/:id` | accounts; the health figures are drawn on a canvas from page data, the metrics API or a script chunk |
| `GET /crm/directory` | customer contacts, rendered by page JS from the directory API, 25 per page, filter box |
| `GET /billing/invoices` (`?status=open\|paid`), `GET /billing/invoices/:number` | invoices; an invoice page embeds the finance note (same-origin frame) and the payment form (payment host frame, which embeds a verification box from the main host) |
| `GET /billing/settings`, `POST /billing/settings` | payout account (admins) |
| `GET /releases` (`?component=`, `?page=`), `GET /releases/:ref` | releases; list rows open their detail page by script (no links) |
| `GET /reports`, `POST /reports/run` (`team`, `period`), `GET /reports/runs/:id` | usage reports, generated by a background job (10-60 s of site time); the report code shows when it is done |
| `GET /data/imports`, `POST /data/imports/:id/run`, `GET /data/imports/runs/:id` | file imports, background job; rejected-row count shows when done |
| `GET /expenses`, `GET /expenses/new`, `POST /expenses` (`spent_on`, `category`, `amount`, `merchant`, `description`) | expense claims; the form's script waits ~3 s before sending; every POST is a new claim |
| `GET /events`, `GET /events/:slug`, `GET /events/:slug/register`, `POST /events/:slug/register` (`form_token`, `name`, `email`, `team`, `dietary`) | registration: each form (token) can be sent once (409 after), at most one registration per 4 s of site time per user (429 + `Retry-After`) |
| `GET /admin/members`, `POST /admin/invites` (`email`, `role`) | members and invitations (admins) |
| `GET /developers` | API documentation (below) |
| `GET /embed/invoice-note/:number` | finance-note frame (same origin) |
| `GET /travel` (`from`, `to` airport codes, `date`, `nonstop=1`; `from_q` / `to_q` = the typed text) | flight search: the From / To boxes need a suggestion picked from the autocomplete (it sets the code), the date comes from a calendar (read-only field; today to +120 days); results in departure order, 6 at a time ("Show more flights"), led by "Fares from $X" (the cheapest itinerary, stops included) |
| `GET /travel/book?flight=&date=`, `POST /travel/book` (`flight`, `date`, `traveler`, `cost_center`), `GET /travel/trips` | booking form (traveler prefilled with you), every POST is a booking; my trips |
| `GET /parts`, `GET /parts/f/:family`, `GET /parts/p/:sku` | spare parts: families, a family's photo grid, a part (photo, price, spec-sheet link) |
| `GET /parts/photo/:id.png`, `GET /parts/spec/:id.csv` | a part photo (drawn from the photo columns); the spec sheet (CSV download: material, finish, weight, max load) |
| `GET /vendors` (`q`, `category`, `status`, `region`, `page`; 20 per page, no larger pages), `GET /vendors/:vendor_id` | vendor registry; contacts, contract end and spend only on the vendor page |
| `GET /markets`, `GET /markets/:symbol` (`expiry`, `strikes=all`), `GET /markets/c/:contract` | treasury desk: watchlist; option chain of one expiry (calls left, puts right; 6 strikes either side of the money unless `strikes=all`); a contract's page (its symbol, quotes, open interest) |
| `GET /embed/verify/:token` | verification frame (main host inside the payment frame; no session needed) |
| payment host `GET /pay/:token`, `POST /pay/:token` (`number`, `exp` MM/YY, `cvc`, `name`; form or JSON) | payment form; Luhn, expiry and CVC checks; one payment per invoice |

## JSON API (session cookie; writes need `X-CSRF-Token`)

| Route | Returns |
|---|---|
| `GET /api/chat/:channel/messages?before=&limit=` | `{channel, hasMore, messages}` oldest first |
| `POST /api/chat/:channel/messages {body}`, `PUT /api/chat/:channel/draft {body}` | post / save draft |
| `GET /api/queues/:slug/rows?offset=&limit=` (<= 100) | `{queue, total, offset, rows}` |
| `GET /api/docs/:slug/conversation` | `{scope, messages, tracker, revisions}` |
| `GET /api/accounts/:id/metrics` | `{account, metrics}`; `GET /assets/crm/acct-<id>.js` is the script-chunk form |
| `GET /api/v2/directory?cursor=&limit=&q=` | `{total, cursor, nextCursor, contacts}`; `/api/v1/*` answers 410 |
| `GET /api/reports/runs/:id`, `GET /api/imports/runs/:id` | `{id, status, started_at, done_at}` |
| `GET /api/v2/vendors?cursor=&limit=&category=&status=&region=&q=` (<= 100) | `{total, cursor, nextCursor, vendors: [{vendor_id, name, category, region, status, contact_email, contract_end, annual_spend}]}` |
| `GET /api/travel/airports?q=` | `{airports: [{code, city, name}]}` (8 at most; city, name or code) |
| `GET /api/travel/flights?from=&to=&date=&nonstop=&offset=&limit=` (<= 6) | `{total, offset, flights}` in departure order |

## Scenario knobs (`POST /__rl/reset {scenario}`)

Variant parameters never come from the URL. Unset knobs use a per-record default.

| Knob | Values | Default |
|---|---|---|
| `widgets.queue` | `unmount` `recycle` `pinned` `sections` `grid` | `queues.widget` |
| `scroll` | `container` `page` (`grid` is always `page`) | page for queue id % 3 == 0 |
| `row_height` | 32-120 px | 52 (`grid`: 30) |
| `widgets.editor` | `shadow` `contenteditable` `textarea` | `channels.editor` |
| `pane` | `open` `closed` (planning-doc conversation pane at load) | `open` |
| `data_source` | `inline` `api` `bundle` (account figures) | `accounts.data_source` |
| `job_seconds` | 1-300 (reports and imports) | 10-60 by record |
| `rerender` | `false` keeps the job spinner element stable | re-created every 1.5 s |
